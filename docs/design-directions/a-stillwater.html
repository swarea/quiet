TypeScript 프로젝트에서 런타임 검증이 필요한 순간들

2025.06.28 · swarea · 댓글 4

TypeScript는 컴파일 시점의 타입만 검증한다. API 응답, 폼 입력, URL 파라미터처럼 런타임에 들어오는 데이터는 타입 시스템의 보호 밖에 있다. 경계에서 한 번 검증하면, 내부 코드는 타입을 신뢰할 수 있게 된다.

경계에서 검증하고, 내부에서는 신뢰한다 — 런타임 검증 라이브러리를 쓰는 이유는 이 한 문장으로 요약된다.

스키마를 코드로 선언하기

예를 들어 사용자 정보를 받는 API가 있다면, 응답 스키마를 이렇게 선언할 수 있다. z.infer로 타입까지 함께 얻는다.

const User = z.object({
  id: z.number(),
  name: z.string().min(1),
  email: z.string().email(),
});
type User = z.infer<typeof User>; // 스키마가 곧 타입

이 접근의 장점은 검증 로직과 타입 정의가 갈라질 수 없다는 것이다. 문서와 구현이 어긋나는 고전적인 문제가 구조적으로 사라진다.
